# Antigravity 取得エラーの解析と改善

調査日: 2026-11-09（日本時間） / 重要度: Major（Antigravity の利用枠表示）

## 現象と確認した事実

- 報告された画面は「取得エラー」「--」「再試行待ち」。他サービスは取得できている。
- 22:47 の Antigravity CLI ログでは、期限切れトークンを更新して認証に成功した後、モデル設定の取得中に記録が途切れていた。`/usage` の実行完了は確認できなかった。
- アプリのキャッシュには同日 01:10 の正常値（3グループ・5枠）が残っていたが、エラー時の表示処理はその値を利用していなかった。
- インストール済み CLI 1.5.3 を再実行すると、6.34秒・5.47秒で正常な利用枠を取得できた。継続的な未ログインや応答形式の全面変更は、今回の確認では見られなかった。

## 原因の評価

| 問題 | 根拠・確度 | 対応 |
|---|---|---|
| 起動・認証更新時の一過性の取得失敗から復帰できない | 旧実装は15秒で打ち切り、CLIを再試行しない。失敗時ログは初期化途中で途切れている。ただし当該プロセスの終了理由そのものは記録されておらず、タイムアウトだったとは断定できない。 | 待ち時間と再試行を改善 |
| 保存値があるのに残量が消える | `ApplyUsage` が Antigravity の失敗時に常に `ApplyUsageError` を呼ぶことを確認。確定した表示処理の不具合。 | 前回正常値と日時を表示 |
| IDE補助取得が最初のプロセスだけに依存する | 先頭のサーバーが未準備・空応答でも、別のサーバーを確認しない構造。今回の直接原因とは未確認。 | 複数サーバーの探索・接続先再検出 |

## 実装した改善

- CLIの待ち時間を30秒に延長。一時的な終了エラー・空応答・タイムアウトでは1秒後に1回だけ再試行する。認証必須・権限・引数エラーは再試行しない。
- タイムアウト時には起動したプロセスツリーを終了し、終了確認後に次を試す。終了確認に失敗した場合は追加起動しない。
- 成否と所要時間をログに残す。CLIの生応答や認証情報はログに転記しない。
- JSON内の `response` に格納された表形式の利用枠にも対応。失敗ステータスと不正な割合を正常値として扱わない。
- CLI起動例外でもIDEによる補助取得を続行する。IDEは複数の接続先を確認し、空応答を成功扱いせず、再起動後は探索し直す。サーバー未起動などの理由をアプリのログに表示する。
- 通信失敗時は Gemini・Argon・外部モデルの前回正常値を保持し、「前回」と取得日時を表示する。「取得エラー」と最終成功時刻は維持し、古い値を最新とは表示しない。取得復帰後は前回表示を解除する。

取得コマンドは引き続き `agy -p "/usage" --output-format json`。参照: [公式の利用枠コマンド](https://antigravity.google/docs/cli/commands/usage/)、[公式の非対話出力仕様](https://antigravity.google/docs/cli/headless/)。

## 検証結果

- 修正前の既存回帰テスト: 101 / 101 成功。
- 修正後: 115 / 115 成功。タイムアウト・一時エラーからの復帰、再試行上限、認証エラー、実プロセスの終了、IDEの複数接続先と再起動、前回値の保存・再読込・復帰を検証。
- 修正した `UsageFetcherService` から実際のCLIに問い合わせ、5.7秒で3グループ・5枠を取得。「取得エラー=False」「取得元：CLI」と画面用データへの反映を確認。検証用キャッシュは作業フォルダー内に分離。

再発時は詳細画面の Antigravity ログで「タイムアウト」「終了コード」「認証または設定」「IDE未起動」と所要時間を確認できる。サーバー側の長時間障害や再ログインが必要な状態では取得失敗は残るが、前回正常値と日時を確認できる。
