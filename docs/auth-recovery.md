# 認証後に詳細画面から復帰できない不具合

- 調査日: 2026/10/01
- 深刻度: Major（認証の問題解消後も利用状況を確認できない）
- 対象: Grokおよび全AI共通の詳細更新処理

## 現象と原因

Grokで認証エラーが発生し、Grok本体で認証を完了しても、このアプリの詳細画面から更新するとエラー表示が残る。アプリを再起動すると解消する。

詳細の「更新を確認」はCLIの状態を調べた後、`FetchUsageAsync`を呼んでいたが、このメソッドは前回取得したデータを再表示するだけだった。認証後の最新データを取得しないため、エラーを解消できなかった。同じ呼び出しを使うCLIのインストール・更新にも影響する。

加えて、GrokはHTTP 401/403を通常の取得失敗として扱っていた。認証ファイルが残っているとログイン済みと判断され、詳細のログインボタンが非表示になっていた。ログイン処理も認証ファイルの存在だけで完了を判断しており、期限切れのファイルで誤判定する。

## 修正

1. 全AIの詳細に「利用量再取得」を追加。対象AIの認証情報・利用状況を実際に取得し、成功時に認証状態とエラー表示を更新する。
2. CLIが導入済みで、未ログインまたは取得エラーがある場合だけ「認証」と案内を表示。Grokは対話起動して認証案内に従えるようにする。
3. 認証コンソールの起動と認証完了を区別。手続き後の再取得を案内する。
4. Grokの401/403は再認証が必要な状態として反映し、古いログによる成功扱いを避ける。トークン更新は取得ごとに最大1回とする。
5. 全体更新と個別操作の重複を抑止し、取得・認証情報更新・キャッシュ保存を直列化する。
6. Claudeの設定ファイルに認証情報がない場合も未ログインとして扱う。詳細の操作名を短くし、ボタンの幅と高さを統一する。

## 検証と再発防止

`tests/AIUsageChecker.RegressionTests`の回帰検証で、全AIの個別実取得、認証・通信エラーからの復帰、全体取得との競合、Grokの偽HTTP応答を確認する。認証・ログ・キャッシュは一時ファイルを使用し、実際のユーザー認証やネットワークに依存しない。

```powershell
dotnet build AIUsageChecker.csproj
dotnet run --project tests/AIUsageChecker.RegressionTests
```

実サービスでの対話認証はユーザーの操作が必要。修正版で「認証」→手続き完了→「利用量再取得」の順に操作する。

検証結果: ビルドは警告・エラーなし、回帰検証は40/40件成功。詳細画面の条件付きボタン表示・無効化・寸法・短い文言と、実ウィンドウを開かないことも確認した。修正版は `bin/Release/compact-actions/AIUsageChecker.exe` に発行。実サービスでの対話認証は未確認。
